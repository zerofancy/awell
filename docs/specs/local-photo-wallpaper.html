本地照片动态壁纸

选择本地照片目录，在现有随机矩形背景上叠加照片，并在每次解锁后随机更换。

版本 0.3 · 2026-10-19 · 基于当前仓库代码 · 本文为设计稿，尚未实现
后续扩展：定时更换壁纸 Spec（已于 2026-10-27 实现）新增独立的定时与解锁开关、启动到期检查与补偿，并将第 8 节的 SharedPreferences 存储建议升级为 DataStore。启用定时后，本文“不定时刷新”以及“恢复可见不换图”的相关约束由新稿覆盖；其余规则继续适用。

1. 目标与范围

  1. 用户通过系统目录选择器选中一个本地目录，并授予应用持续访问该目录的权限。
  2. 保留黑色底色与 10 个随机彩色矩形的绘制规则；背景与照片使用同一次更新事件，每帧先绘制背景，再绘制当前照片。
  3. 每次用户完成解锁，从目录中随机选择照片；有多张可用照片时避免与当前照片相同。
本版默认决策，待产品确认：“管理权限”解释为持久读取所选目录，不包含删除、移动或修改照片；照片居中等比完整显示。若需要目录写入管理或铺满裁切，应调整本文后再实现。目录范围已确认：递归包含所选目录下所有可访问的子目录。

本版不增加定时换照片、网络图库、视频播放、切换动画或多目录管理。取消矩形背景每 60 秒独立刷新；背景与照片统一在解锁、首次初始化、目录变更或当前文件失效时更新。恢复可见和尺寸变化只重绘现有内容，不触发随机更新。

3. 用户流程与页面状态

  1. 首页展示“照片目录：未选择”，提供“选择照片目录”和“设置动态壁纸”。未配置目录时仍可使用矩形壁纸。
  2. 点击选择目录，打开系统目录选择器；用户选择目录并确认授权。
  3. 持久授权成功后校验可读性并保存配置，异步递归扫描照片。页面展示目录名称、包含子目录的可用候选数量或错误原因。
  4. 目录可读即完成替换；空目录也可保存并明确提示。已运行的壁纸收到配置变化，清除旧目录照片并加载新目录的首张随机照片。
  5. 点击“设置动态壁纸”进入现有系统预览，由系统完成应用壁纸。
  6. 后续解锁自动换图，无需再次打开应用。更换目录复用同一选择器，取消操作保留原配置与照片。

4. 目录授权与文件访问

  • 使用 Storage Access Framework 的 ACTION_OPEN_DOCUMENT_TREE。通过结果中实际授予的标志调用 takePersistableUriPermission，持久化读取权限；无需申请全盘管理权限或额外的广泛媒体读取权限。
  • 保存 content:// tree URI，通过 ContentResolver / DocumentsContract 枚举和打开文件，不将 URI 转为文件系统绝对路径。
  • 先取得并验证新目录的持久读取授权，再原子替换配置。授权失败保留旧配置；旧目录的任务退出后释放不再使用的旧授权。重复选择同一目录不得误释放当前授权。
  • 遵守 Android 11 起系统对根目录、Download 目录及 Android/data、Android/obb 等位置的选择限制，提示用户选择可授权的照片文件夹，不绕过系统限制。
  • 本版面向设备共享存储与可访问的 SD 卡目录；不开发云相册接入。系统提供者是否本地不能仅凭 URI 可靠断言；异常提供者走读取失败与超时回退。
  • URI 配置恢复后必须验证持久授权；备份恢复或重装不视为授权仍然存在。应用不得删除、移动、改写用户照片。

平台依据：Android · 目录访问、持久 URI 授权与系统限制。

5. 照片筛选与随机规则

  • 递归枚举所选目录及所有可访问子目录中的普通图片文档；目录节点仅用于遍历，不作为照片候选，不加载视频或虚拟文档。按图片 MIME 类型筛选；提供者缺失或返回通用 MIME 时可按扩展名补充候选，最终以解码结果为准。
  • 首版必验 JPEG、PNG、WebP；其他静态图片仅在当前系统解码器支持时使用。动图只显示首帧，不承诺动画与 RAW 支持；支持照片的 EXIF 旋转与镜像。
  • 每次换图前递归刷新候选列表，使任意层级新增、删除的文件在下次成功扫描后生效。不后台轮询目录，也不保证外部改动立即反映到当前画面。
  • 将各层级图片合并为同一个候选池，按文档身份去重；随机以照片为单位，不先随机选子目录，避免不同大小目录造成抽样偏差。多张时排除当前 URI 后均匀随机抽取；允许隔次重复，不保证遍历完所有照片才重复。
  • 只有一张时持续显示该图；没有照片时显示矩形背景。首次配置或首次应用且无当前图时，立即随机选一张，不等待解锁。
  • 解码失败的候选在本轮不再尝试；从剩余候选继续随机选择，直到成功或全部失败。本轮排除当前图的候选均失败时，允许保留仍可用的当前图。
  • 一次换图任务设置可配置的总超时（建议初值 5 秒），超时则保留旧图并记录原因。文件已确定被删除、目录失效或已切换时不保留旧图。

遍历使用显式队列或栈，并按提供者与 document ID 记录已访问目录，避免深层目录导致调用栈溢出、重复遍历或循环引用；遍历仅限已授权的目录树，不访问树外位置。单个子目录不可读时跳过并标记“部分目录无法读取”，其余可访问目录继续参与；根目录授权失效仍按权限失效处理。

扫描过程支持取消，总超时包含递归枚举与解码。超时不得将截断的候选列表标记为完整扫描结果，也不从截断列表抽样；保留上一组画面并提示扫描未完成，下次有效更新重试。不设置静默的遍历深度限制。

6. 绘制与资源约束

一次有效帧
  1. 清屏为黑色
  2. 绘制当前 10 个随机矩形
  3. 绘制已解码的当前照片（如有）
  4. 提交 Canvas

矩形的数量、颜色范围与坐标随机规则保持，取消独立计时刷新。背景和照片共用更新请求：新照片准备完成后，生成新的 10 个随机矩形，并将背景与照片作为同一组状态原子提交，不能先显示新背景再等待照片。仅亮屏、恢复可见或 Surface 重建不重新随机生成矩形。

每个更新请求只提交一次背景与照片状态。单图目录允许沿用唯一照片，空目录或未选目录允许无照片，这些情况下每轮有效更新仍生成一次背景。读取超时或全部候选解码失败且保留旧图时，整组旧画面保持不变；若必须清除失效照片，则将无照片状态与新背景一起提交。取消或过期请求不能单独改变背景。

照片使用 FIT_CENTER：方向纠正后的尺寸为 w × h，画布为 W × H，缩放比 s = min(W/w, H/h)，居中绘制为 w·s × h·s。完整保留照片、允许放大，不拉伸，不额外加边框；未覆盖区域与透明区域透出矩形背景。照片恰好铺满时，背景被覆盖符合预期。

  • 枚举、文件读取和解码在后台执行，禁止在广播回调、主线程或持有 Canvas 锁时进行 I/O。
  • 按实际 Surface 尺寸降采样，禁止无条件解码原始超大图。仅保留当前显示图与一次候选图；建议合计像素缓冲预算不超过 min(32 MiB, 应用最大堆 / 8)，含方向变换临时缓冲，必要时进一步降采样。
  • 串行提交绘制；仅在 Surface 有效且 Engine 可见时锁定 Canvas，成功获取后用 try/finally 确保提交释放。Surface 无效时保留状态，下一次可见时绘制。
  • 新背景与新图准备好后原子替换整组画面，避免空白过渡；Bitmap 不得在绘制期间回收。不保留背景定时任务，不因每次恢复可见重新解码同尺寸照片。
  • Surface 尺寸变化时重算布局，必要时重新采样当前 URI，不重新随机选图或生成矩形；矩形保存归一化坐标，以适配新画布。Engine 销毁时取消任务并释放图片资源。

7. 解锁与生命周期

以系统 ACTION_USER_PRESENT 作为解锁后用户可用事件，在 WallpaperService 存活期间动态注册接收器，并在销毁时注销。接收器只向状态协调器发送事件；不能在回调内扫描或解码。onVisibilityChanged(true) 只负责恢复绘制，不能直接触发随机换图。

事件照片行为
收到一次有效 USER_PRESENT生成一次选择请求，基于最新目录换图并同步更新矩形背景；多个正式 Engine 共享同一轮照片选择与背景随机结果。
解锁时壁纸被前台应用遮挡记录待切换请求，待正式 Engine 可见时执行；多次不可见解锁合并为最近一次，不解码不可见中间帧。
仅亮屏、仍在锁屏不换图；生物识别或密码完成后收到事件才换。
从应用返回桌面 / 横竖屏切换 / Surface 重建沿用当前 URI 与矩形状态，只重绘、适配布局或重新采样。
壁纸服务重建 / 重启设备恢复目录与最近成功的照片 URI；仍有效则沿用，无效则重新选择。背景随恢复画面初始化一次。与系统首次可用事件合并，避免初始化和解锁产生两次可见切换。
系统壁纸预览可展示所选目录照片，但预览不消费正式解锁事件，不写正式最近照片，也不影响已应用壁纸。

用目录版本与请求序号拒绝过期异步结果；切换目录、Engine 销毁或后续事件到达时，旧任务即使未及时取消也不得覆盖新状态。预览与正式壁纸分离；Service 级协调器只为正式 Engine 消费解锁事件。

平台边界：可见性不等于解锁。服务未存活时不能可靠回补全部历史解锁；进程恢复以恢复当前状态为准。无安全锁屏、厂商自定义锁屏及特定仅锁屏壁纸场景，须真机验证 USER_PRESENT 的投递时机。首版不把任意亮屏伪装成解锁；未投递该事件的设备不能宣称已满足自动换图验收。

平台依据：Intent.ACTION_USER_PRESENT；Engine 可见性回调。本文事件合并、预览隔离与回退规则为项目设计决策。

9. 验收标准与验证步骤

ID步骤预期
AC-01首次启动，未选目录，打开壁纸预览并应用。仍可使用原矩形背景，不因缺少照片失败。
AC-02选择含 3 张不同照片的本地目录，应用壁纸；重建进程并重启设备。无需重复授权；恢复有效目录和照片，授权失效时有明确入口。
AC-03更换目录时取消选择；再模拟持久授权失败。两种情况均保持旧配置与照片，不误释放旧授权。
AC-04分别加载横图、竖图、透明 PNG、带旋转/镜像方向的 JPEG。照片方向正确、居中完整显示；空白和透明处透出矩形，绘制顺序正确。
AC-05配置 3 张可读照片，完成 10 次锁屏解锁；覆盖指纹/人脸与密码。每次收到有效解锁事件仅切一次，与上一张不同；候选随机规则由可注入随机源验证。
AC-06仅亮屏停留锁屏；多次打开应用再回桌面；改变 Surface 尺寸。背景和照片均不随机更新；尺寸改变只调整采样和布局。
AC-07壁纸持续可见超过 120 秒且不解锁，再完成一次解锁换图。等待期间背景与照片均不变化；解锁后照片与新矩形背景在同一帧生效，不出现独立的定时刷新。
AC-08分别选择空目录、单图目录，以及照片分布在根目录和多层子目录、含坏图与非图片的目录；另测根目录无图但子目录有图。空目录只显示背景；单图保持照片不变，但每轮有效解锁同步刷新背景；空目录在同样事件下更新背景；各层级可用照片均进入同一候选池；根目录无图不判为空目录；坏图跳过，非图片不参与。
AC-08a构造深层目录、重复目录引用、不可读子目录以及递归扫描超时；在子目录中增删照片后解锁。无栈溢出或重复候选；不可读子目录不影响其余目录且标明部分不可读；超时保留整组旧画面；下一次成功扫描反映子目录增删。
AC-09删除当前照片、添加新照片后解锁；撤销授权或移除 SD 卡。下一次扫描反映增删；权限失效回退背景，临时存储错误可恢复，无崩溃或反复提示。
AC-10前台应用遮挡桌面时解锁，再返回桌面；解锁与可见回调紧邻。待处理请求在可见时生效，两个事件不造成重复换图。
AC-11模拟慢读取时快速更换目录、解锁及销毁 Surface；同时打开预览。过期结果不能回写；无并发 Canvas 锁与资源误回收；预览不改变正式选择。
AC-12使用高像素照片与 1,000 个文件的目录，记录加载耗时和内存；隐藏壁纸。无主线程 I/O、ANR 或原图无界解码；符合预算与超时回退；隐藏时停止定时绘制。

纯逻辑测试覆盖随机边界与过期请求拒绝；设备测试覆盖 SAF 授权、重启恢复、解码与 Surface 生命周期。至少覆盖 API 23、30、33 与 targetSdk 37 对应系统，并在实际目标设备验收锁屏投递；缺失设备的结果明确标记未验证。以静态代码检查代替不了解锁真机验收。

10. 待确认项与交付顺序

  1. 权限含义：本版只读是否符合“管理权限”？若要删图或整理目录，需单独设计写权限与用户操作。
  2. 照片布局：默认完整居中以显露背景；是否希望改为铺满裁切？
  3. 目标锁屏行为：需在主要设备确认有锁/无锁、仅桌面/桌面与锁屏的预期与系统投递情况。
