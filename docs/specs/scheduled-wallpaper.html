定时更换壁纸

保存一个计时基线，启动和恢复可见时检查到期条件。到期补换一次，成功后重新计时。

版本 0.4 · 实现于 2026-10-27 · DataStore · 自动化验证范围见文末

2026-10-31 扩展：背景可选“随机矩形”或“模糊拉伸”，纯背景切换不换图、不重新计时。本文中固定矩形及单图随机背景的相关描述，以模糊拉伸背景 Spec为准。

两个开关独立

解锁更换与定时更换可以分别启停；任一有效换图成功，都重新开始定时周期。

仅一个时间字段

保存本轮计时起点。下一次到期时间和剩余时间直接计算，不维护额外版本或历史记录。

启动先检查

进程退出不丢计时依据；恢复时若已到期，在正式壁纸可绘制后立即补换一次。

范围设置最小字段计时规则启动与调度DataStore实现边界验收

1. 本次范围

在现有本地照片动态壁纸上增加定时更换，以及解锁更换开关；使用 DataStore 保存目录、设置、最近照片与计时基线。继续使用 Kotlin，沿用当前照片扫描、解码、随机选择、背景合成和预览隔离。

本文扩展本地照片壁纸 Spec，替代旧稿的 SharedPreferences 存储建议；启用定时后，旧稿“不定时刷新”及“恢复可见不换图”的对应约束由本文覆盖。本次不做固定时刻、后台精确唤醒、进程保活、换图历史或多时钟兼容机制。

2. 设置

项目规则
解锁时更换独立开关，默认开启，保持现有行为。
定时更换独立开关，默认关闭；首次开启默认每 1 小时。
更换间隔15 分钟、30 分钟、1 小时、6 小时、24 小时；关闭定时时禁用间隔控件，保留所选档位。
说明“每次成功更换后重新计时。壁纸暂不可见或应用未运行时，下次显示时检查并补换。”

两个开关独立、任一成功换图后重新计时已确认；默认值和间隔档位按本稿建议。设置保存成功后更新 UI，失败保留原设置并提示。两个开关都关闭时仍允许首次初始化、目录变更和失效修复。

3. 最小持久字段

保留 7 个字段，其中目录和最近照片是现有数据，本次新增 4 个字段。DataStore 使用单个不可变 WallpaperState，通过 Kotlin Serialization JSON 序列化。

字段用途
directoryUri: String?已选择目录的 URI，沿用现有数据。
directoryName: String?目录展示名，沿用现有数据，避免页面展示时重新读取提供者。
currentPhotoUri: String?最近正式照片，沿用现有数据；null 表示当前无照片。
unlockEnabled: Boolean解锁更换开关，默认 true。
timerEnabled: Boolean定时更换开关，默认 false。
intervalMillis: Long所选间隔，默认 1 小时；仅接受支持的正值档位。
timerBaseAtMillis: Long?本轮计时起点的 epoch 毫秒值，定时关闭时可为空；开启时或有效换图成功后更新。

不另存 lastChange、ClockMark、bootCount、currentScene、初始化标记、版本计数、下一次到期时间或剩余时间。当前没有展示换图历史的需求，不必区分“最后换图时间”和“本次启用时间”；统一称为计时基线，不将启用开关称为换图成功。

4. 计时规则

due = timerEnabled
      && timerBaseAtMillis != null
      && nowMillis - timerBaseAtMillis >= intervalMillis

remaining = max(0, timerBaseAtMillis + intervalMillis - nowMillis)
事件处理
开启定时保存基线为当前时间，等待一个完整间隔；不立即更换已有照片。
关闭定时取消定时等待并清空基线；解锁开关仍独立生效。
更改间隔沿用原基线重新判断；缩短后已到期则待可绘制时执行，延长后等待剩余时间。
解锁、定时、首次初始化或修复成功照片与背景一起更新；定时开启时，将照片 URI 和当前时间基线通过同一次 DataStore 事务保存。
恢复旧图、空背景或重建 Surface不改变基线；不能因为每次重建而不断推迟到期。
单图、空目录或未选目录的有效换图允许照片 URI 不变或为空；更新一次随机背景，也算成功并重新计时。
读取或保存失败保留可用旧画面和原基线，不将失败记为成功。定时开启且可见时，用同一个计时 Job 等待 1 分钟后重试；不做多级退避。

例如间隔 1 小时，10:00 开始计时，10:40 解锁换图成功，则下一次定时为 11:40。离线到 15:00 才恢复时只补一次，成功后再等 1 小时。

若定时已开启但基线缺失，只补写当前时间作为基线；启动时读到有效基线则保留，不无条件重新计时。

首版统一使用系统 epoch 时间，不持久化单调时钟或启动次数。用户手动向前调时可能提前到期；若当前时间早于基线，则将基线校正为当前时间并等待完整间隔。时区只影响显示。接受手动改时导致的间隔偏差，不扩展多时钟状态。

5. 启动检查与可见时调度

等待 DataStore 首次有效状态及旧数据迁移完成
  → 检查定时开关、基线和当前时间
  → 已到期：准备一次新选择
  → 未到期：恢复最近照片或背景，不重置基线

正式壁纸可见且 Surface 就绪时执行
  → 成功：保存照片与新基线，提交画面
  → 暂不可绘制：等待可见 / Surface 回调后重新检查
  • 入口：WallpaperService 创建、正式 Engine 附着、恢复可见和 Surface 就绪时检查。Activity 启动读取同一状态；没有正式 Engine 时只显示设置，等待系统创建壁纸。
  • 启动已到期：不再等待完整间隔；用持久化的旧 URI 排除连续重复，首个正式可绘制的 Engine 就绪后立即开始异步准备。漏过多个周期只补一次。
  • 启动未到期：恢复旧 URI。URI 为空时可执行一次恢复性扫描；仍为空只恢复背景，不更新基线；找到可用照片或旧照片失效需换新时，按初始化 / 修复处理。目录选择后继续沿用现有首次加载入口，不增加持久初始化标记。
  • 可见期间：在现有协调器内增加一个单次等待 Job，到时重新判断条件。配置 Flow 变化后调整等待；时间经过本身不会触发 DataStore Flow。
  • 隐藏或销毁：取消等待及无用准备，不扫描不可见中间帧；不清除持久基线。进程重建、设备重启或强行停止后再次可用，都按同一启动检查恢复。
  • 事件合并：复用已有待处理和取消机制；同一在途换图期间的解锁、到期和生命周期事件合并一次。恢复旧图期间收到有效换图事件时，应改为换图，不能把事件吞掉。不增加固定 1 秒合并窗口。
  • 预览：继续使用独立临时状态，不写正式照片或计时基线。

目录无权限时沿用现有状态提示和背景回退，等重新授权或下一次有效入口再校验，不循环扫描。暂时读取失败使用上述固定重试等待；全部隐藏时取消重试，恢复可见再判断。

平台依据：Android 建议动态壁纸在可见时使用 CPU。本稿采用可见时执行、恢复时补换的产品规则。

6. DataStore 与迁移

应用内同一文件只创建一个 DataStore 实例，由现有 PhotoDirectoryRepository 统一访问，Activity 与壁纸服务复用。读取以 data Flow 为准，修改使用 updateData；不额外维护可写缓存。首次读取失败时显示错误并重试，不把临时错误当成默认配置覆盖原数据。

扫描和解码在事务外执行；准备完成后，通过现有协调器串行提交。在 updateData 中使用最新状态，仅修改相关字段，同时检查本轮依赖的目录与设置仍适用。复用现有进程内请求 token 拒绝取消后返回的旧结果，目录重选时也应使旧请求失效；无需持久化请求版本。

照片 URI 和新基线同一次提交，保存成功后再发布场景。落盘前进程死亡则恢复旧记录，落盘后、绘制前死亡则恢复新记录；调用方被取消而无法确认结果时，下次先读取 DataStore 再判断。这里的成功指可恢复的逻辑提交，实际屏幕显示仍需设备验收。

用 SharedPreferencesMigration<WallpaperState> 迁移现有 photo_directory 中的 tree_uri / tree_name / last_photo；新设置采用默认值，不推测旧图展示时间。迁移幂等、目标已有值优先，持久成功后清理旧 key 并停止旧偏好读写，不释放仍在使用的 SAF 授权。

Serializer 为缺失字段提供默认值，实际出现不兼容格式时再设计迁移；已知格式损坏与普通 I/O 失败分开处理。整个 DataStore 文件放入 noBackupFilesDir，旧偏好也从备份与设备迁移中排除，不为备份另建一套状态。

平台依据：DataStore 的单实例、不可变数据与 Flow；updateData 的事务与持久化语义。

7. 实现边界

  • 数据层：增加 WallpaperState 与 JSON Serializer，现有 PhotoDirectoryRepository 改用 DataStore，继续负责目录授权和扫描。
  • 协调器：在 WallpaperPhotoCoordinator 中增加设置订阅、到期判断和单次等待；复用已有照片任务、pending、取消和 token。到期计算用可传入当前时间的简单函数测试。
  • 界面与文档：MainScreen 增加两个开关和间隔选择；实现时同步 README 与备份规则。无需单独拆 RotationPolicy、RotationClock、RotationScheduler 或通用状态机框架。

沿用现有 5 秒扫描解码超时、照片和矩形背景整组更新、资源预算与过期结果校验。目录失效、坏图、Surface 生命周期等既有处理继续复用，不在本次重新设计。

8. 必要验收

ID验证
T-01默认值和四种开关组合正确；成功解锁换图重启定时，关闭定时不影响解锁。
T-02未到期终止并重建进程：保持旧 URI 和基线，只等待剩余时间。
T-03已到期或漏过多周期后重建：首个正式可绘制时立即补换一次，多图时排除持久旧 URI。
T-04隐藏 / 无 Surface 时不换；恢复可见时检查。反复恢复旧照片或空背景不推迟基线。
T-05缩短 / 延长间隔沿用基线；加载中改目录或设置，旧请求不回写；同时到达的在途事件合并。
T-06单图和空目录的有效更新重新计时；单纯恢复不重新计时；预览不修改正式状态。
T-07读取或保存失败不更新基线、不零间隔循环；暂时失败按固定等待重试，权限失效提示重新授权。
T-08SharedPreferences 迁移保留目录与最近照片；首次读取完成前不执行默认策略；写入前后重建恢复一致记录。
T-09手动向前 / 向后改时间按基线规则处理；设备重启后仍能检查是否到期。
T-10真机验证系统重建、实际 Surface 与照片背景同步显示；已有照片与资源相关测试继续通过。

逻辑测试注入当前时间和短等待，避免真实等待长周期；设备验证补一次正式间隔。沿用构建、单元测试、lint 与相关设备测试。策略或假 Engine 测试不能替代真实系统壁纸显示验收。
