AWELL / FEATURE SPEC / IMPLEMENTED

完整照片 + 模糊拉伸背景

将同一张照片作为柔和的铺满背景，填补比例不同产生的留白。前景照片保持完整、清晰和原始比例。

v1.0 · 2026-10-31 · 已实现 · 自动化与真机验证范围见第 8 节
核心约定：“模糊拉伸”是背景效果名称：底层等比放大并居中裁切铺满，前景等比缩放并完整居中。前景不裁切、不做横纵不等比拉伸。与现有“随机矩形”作为两个互斥选项。

本稿承接关联聊天“优化照片桌面背景适配”中“完整照片 + 同图模糊背景”的方向，扩展现有本地照片壁纸 Spec与定时更换壁纸 Spec。本文覆盖两份旧规格中固定使用随机矩形背景的描述。

项目本稿约定
背景选项“随机矩形”“模糊拉伸”，同级、单选，全局生效。
默认选择新安装和旧版本升级均为“随机矩形”，保留现有默认外观。关联聊天中的默认模糊建议不直接改变已有产品默认值。
首版参数模糊程度、压暗程度使用固定值；本稿建议的起始值见第 4 节，需用真机样张确认。
延续行为本地 SAF 读取、照片随机选择、解锁与定时规则、系统预览和正式壁纸均继续使用现有流程。

4. 绘制规则

4.1 前景与背景分层

以当前壁纸 Surface 的实际绘制尺寸为目标，不用 Activity 内容区域或固定手机比例。先沿用现有 EXIF 方向修正，前景与背景都从同一份已修正照片派生。

输入：目标 W × H，已修正照片 w × h

前景：sFit = min(W / w, H / h)
      宽高 = w × sFit, h × sFit；居中、完整显示

背景：sFill = max(W / w, H / h)
      宽高 = w × sFill, h × sFill；居中裁切至目标
      模糊 → 叠加 22% 不透明度黑色遮罩

绘制：不透明黑底 → 选定背景 → 清晰前景

这里的“拉伸”不使用非等比变形。背景铺满允许裁切；前景无额外边框、阴影、圆角或模糊。黑色遮罩只影响背景，绘制前景前必须恢复 Paint 等状态。

4.2 模糊起始参数

  • 建议先用低分辨率背景缓存：长边最多 256 像素，另一边按 Surface 比例计算且至少为 1；不为背景再次全尺寸解码原图。
  • 在背景缓存尺寸上做三轮可分离盒式模糊，每轮半径为 max(1, round(缓存短边 × 0.04))。作为首版统一起始效果，避免不同屏幕尺寸导致明显模糊差异。
  • 边缘使用最近边界像素延展后参与模糊；模糊不能在屏幕边缘引入透明或黑色边框。
  • 生成背景前先以黑底合成带透明通道的照片，再裁切模糊；清晰前景仍保留原透明通道。全透明图片的模糊背景为黑色。

实现可在保持视觉与资源约束的前提下调整算法；最终参数需用风景、人像、夜景与纯色样张验收，再统一记录。首版不增加用户可调参数。

5. 事件、提交与失败

事件画面行为正式照片与计时
仅切换背景选项从当前已显示照片生成背景，准备完成后整帧替换。处理期间保留完整旧画面。不选新图、不重新扫描目录、不写 currentPhotoUri、不改 timerBaseAtMillis。
解锁 / 定时 / 初始化 / 目录修复的有效更新选定照片与对应背景作为一组提交；模糊失败可按黑底降级提交清晰照片。成功的照片更新沿用现有计时规则。
单图目录触发有效更新随机模式刷新矩形；模糊模式可复用同图缓存，视觉可能完全相同。仍算有效更新，按既有规则重置开启中的定时基线；与旧稿“每次刷新随机背景”的差异以本条为准。
空目录触发有效更新随机模式刷新矩形；模糊模式仍为黑底。沿用旧规格中有效空目录更新的计时规则。
重绘 / 恢复可见 / Surface 尺寸变化普通重绘复用缓存；尺寸变化按新目标重建背景，前景继续完整居中。单纯恢复或重绘不改计时；已到期时继续执行现有补换规则。
整张照片读取临时失败沿用现有保留上一组画面与重试规则；旧照片的背景只能与旧照片一起保留。不将失败记为成功，不推迟计时。
确认权限失效或当前照片不可用沿用现有失效修复流程；需清除照片时，模糊派生背景也必须清除。按现有权限、修复与持久化规则处理。

背景更新与换图可以相互取消准备任务，但不能吞掉已收到的解锁、更换目录或已到期请求。例如定时已到期时切换背景，仍应完成一次到期换图，而不是把它变成仅样式刷新。旧异步结果必须同时校验照片场景、背景选项、Surface 尺寸与请求 token，不能覆盖新场景。

多个正式 Engine 共享选项与照片选择，各自维护对应尺寸的缓存；预览维持独立照片场景。模式切回随机矩形时，优先复用当前场景原有的矩形列表；下次有效换图才重新生成。进程重建不要求恢复完全相同的矩形布局。

6. 实现建议与兼容性

6.1 最小持久化扩展

WallpaperState 新增一个 backgroundStyle: String = "random_rectangles"，支持 random_rectangles 与 blurred_photo。使用稳定存储值映射到 Kotlin 中的类型，避免直接依赖枚举反序列化导致未知值使整个配置不可读。

旧记录缺失字段默认随机矩形；未知字符串只将该字段归一为随机矩形，保留目录、照片与全部自动更换设置。真正格式损坏仍沿用既有错误流程。无需新建存储文件或增加持久缓存、模糊参数、请求版本。设置写入通过现有 Repository 的单字段 updateData 完成。

6.3 资源与生命周期

  • 继续覆盖项目当前 minSdk 23 起的支持范围。建议以 Kotlin 软件模糊作为统一路径，不引入仅新版系统可用的必要依赖。
  • 扫描、解码和模糊在绘制锁之外执行；重绘只消费就绪结果，不在主线程逐像素模糊、不持续刷新静态画面。
  • 现有预算按 min(32 MiB, maxMemory / 8) 再按 4 个 Engine 预留划分。新增背景、旧新前景和临时像素数组都计入同一预算，不能在原有三缓冲估算外叠加无上限分配。256 × 256 的单张 ARGB 缓存上限约 256 KiB，工作数组另算。
  • 换图、改样式、改尺寸、隐藏或销毁时取消无用任务。共享前景像素期间须保证其未被 recycle；替换后释放旧缓存，不能同时由多个所有者释放。
  • 缓存以当前照片场景、模式和尺寸为依据；仅 URI 相同不足以跨有效重新加载复用，避免源文件内容更新后仍显示旧背景。无需磁盘缓存或全局图片缓存。
  • 隐藏时不启动背景生成，恢复可见后按最新配置处理。模糊不能额外延长现有 5 秒扫描解码准备期限；到期限时若照片已就绪，可黑底降级。降级后普通重绘不循环重试，下一次重新加载或样式切换再尝试。
