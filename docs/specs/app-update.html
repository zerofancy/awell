AWELL / FEATURE SPEC

应用更新

AWell 通过 KMP Updater 查询新版 APK。发现新版本时展示版本和发布说明，由用户选择是否打开浏览器下载。

2026-11-07 · 版本 0.2 · 手动检查

设计决定用户流程接入配置 服务登记与发版验收

1. 设计决定

  • 最低系统。当前 AWell 支持 Android 6.0（API 23），上游 SDK 最低支持 Android 7.0（API 24）。将 AWell 的 minSdk 提到 24。API 23 设备可继续使用已安装旧版，但无法安装后续版本，也收不到新增的应用内更新提示。
  • 检查时机。用户点击「检查更新」时发起查询。应用启动、进入前台、壁纸服务启动、解锁和定时换图均不触发查询。
  • 服务标识。软件内部名使用 awell，显示名使用 AWell。

2. 用户流程

主界面底部新增「应用版本」区，显示当前版本和「检查更新」按钮。检查期间显示进度并禁用重复点击。查询独立于照片目录和壁纸设置状态。

查询结果用户看到的反馈
有新版前台显示 SDK 中文弹窗，列出当前版本、新版和可用的发布说明。选择「前往下载」时由系统浏览器打开服务返回的 HTTPS 链接。浏览器无法打开时保留弹窗，允许重试或复制链接。
已是最新版服务端版本相同时显示「当前已是最新版本」，服务端版本更低时显示「暂无可用更新」。
没有匹配包手动检查提示「暂无适用于当前安装版本的更新包」。
查询失败手动检查提示失败，用户可再次检查。软件未登记、超时、网络断开和响应异常归为失败。
架构不支持显示「此设备暂不支持检查更新」，跳过网络请求。

界面退到后台时暂缓弹窗，回到前台再展示尚待处理的结果。用户关闭弹窗后，可通过手动检查重新打开。下载与安装由浏览器和 Android 安装器接手。

3. 接入配置

项目配置与约束
SDK使用 io.github.zerofancy:kmp-updater-compose:0.1.0-SNAPSHOT，由它传递引入核心。以本机源码提交 d4f28d0 为构建基线。新环境先在该 SDK 仓库运行 ./gradlew publishToMavenLocal，AWell 将 Maven Local 限定为该 SDK 的模块。
更新服务https://zp.ntutn.top，公开接口 GET /api/v1/updates。客户端只发送软件内部名、系统、架构和包类型。后台凭据仅用于服务管理。
版本与目标从当前构建的 BuildConfig 读取版本，versionCode 转为 Long 比较，versionName 用于展示。目标由 SDK 检测，支持 Android / ARM64 和 Android / X86_64，包类型固定为 apk。
界面与生命周期由主界面的 ViewModel 持有 SDK 的 UpdateController 和 checker，跨旋转保留在途请求与提示。ViewModel 清理时释放 controller 并关闭 checker。UpdateHost 只在前台挂载。旋转和后台恢复均不重新发起查询。使用 SDK 自带的查询超时与限流处理。
构建兼容检查合并 Manifest 的 INTERNET 权限及 Compose 依赖解析。可覆盖安装的正式签名 Release 才启用线上检查。Debug 默认仅显示版本。用 -PupdateTestServer=true 构建时，默认追加包名后缀 .updatetest，并查询设备的 http://127.0.0.1:18763。用 adb reverse tcp:18763 tcp:18763 连接电脑上的测试服务。明文查询只在 Debug 的回环地址放行，下载链接仍须使用 HTTPS。

4. 服务登记与发版

  1. 线上软件为 awell（ID 8）。AWell 1.0.1（2）已发布，分发 ID 为 8，安装包 ID 为 11。Android ARM64 和 X86_64 查询均返回同一份签名 APK。
  2. 正式发版时使用 top.ntutn.awell 和已分发版本兼容的签名证书。核对现有发布记录及 APK 的版本号后，为新版分配严格递增的 versionCode。本次从带有更新入口的 1.0 (1) 签名包升级到 1.0.1 (2)。
  3. 在现有服务中发布 apk 分发，按 APK 实际支持的 ABI 配置 Android 目标。若同一 APK 已验证支持 ARM64 和 X86_64，可给同一个包配置两个目标。填写面向用户的纯文本发布说明，供 SDK 弹窗展示。
  4. 逐个查询实际发布的目标，核对版本、下载链接、APK 的包名和签名。首次发版前，可在测试环境用两个同签名版本验证从查询到覆盖安装的路径。

首个含 SDK 的版本仍需通过原分发方式送达。安装该版本后，AWell 才能主动发现后续新版。

5. 验收

2026-11-07 在 NX888J（Android 16，ARM64）验证 1.0 (1) 手动检查、Fennec 下载、Android 安装器覆盖安装及升级后再次检查。下载文件 SHA-256 与签名包一致，首次安装时间与测试设置均保留，1.0.1 (2) 显示「当前已是最新版本」。X86_64 已验证线上查询。

  1. 按约定从 SDK 源码发布 Maven Local 后，AWell 能构建 Debug 和正式签名 Release。确认合并权限、最低 API 与包名符合设计。
  2. 在受支持 Android 目标上验证高版本、相同或较低版本、无匹配包、离线或超时。确认不支持的架构不发送查询。
  3. 验证启动和恢复前台时无更新查询，手动检查有结果反馈。旋转、退到后台再恢复和连续点击时，检查触发和弹窗数量符合约定。
  4. 在同签名测试包上验证浏览器打开链接、下载及覆盖安装。覆盖安装后核对版本、已选照片目录和壁纸设置。
  5. 服务登记后检查公开 API 返回预期状态。若已有正式分发，核对每个目标返回的 APK 版本和下载链接。
