AWELL / FEATURE SPEC

应用更新

AWell 通过 KMP Updater 查询新版 APK。发现新版本时展示版本和发布说明，由用户选择应用内下载或浏览器下载。应用内下载完成后可点击「安装更新」，交由 Android 系统确认安装。

2026-11-22 · KMP Updater v0.3.0 · 下载校验与 SDK 安装交接

设计决定用户流程接入配置 服务登记与发版验收

1. 设计决定

  • 最低系统。AWell 和 KMP Updater 最低支持 Android 7.0（API 24）。
  • 检查时机。用户点击「检查更新」时发起查询。应用启动、进入前台、壁纸服务启动、解锁和定时换图均不触发查询。
  • 服务标识。软件内部名使用 awell，显示名使用 AWell。

2. 用户流程

主界面底部新增「应用版本」区，显示当前版本和「检查更新」按钮。检查期间显示进度并禁用重复点击。查询独立于照片目录和壁纸设置状态。

查询结果用户看到的反馈
有新版SDK 中文弹窗显示当前版本、新版和发布说明。可在应用内下载并查看进度、取消或重试，也可改用浏览器下载。下载与校验完成后点击「安装更新」。Android 8.0 及以上首次需要授权时，可点击「打开安装权限设置」，允许后返回应用再点一次「安装更新」。系统安装器负责最终确认。取消授权或安装后，可以复用已下载的 APK。浏览器无法打开时可重试或复制链接。
已是最新版服务端版本相同时显示「当前已是最新版本」，服务端版本更低时显示「暂无可用更新」。
没有匹配包手动检查提示「暂无适用于当前安装版本的更新包」。
查询失败手动检查提示失败，用户可再次检查。软件未登记、超时、网络断开和响应异常归为失败。
架构不支持显示「此设备暂不支持检查更新」，跳过网络请求。

界面回到前台时重新展示尚待处理的结果。关闭弹窗后可手动检查。应用内下载由 SDK 负责，安装由用户操作发起。浏览器下载和安装分别由浏览器及 Android 系统处理。

3. 接入配置

项目配置与约束
SDK通过 JitPack 获取 com.github.zerofancy.kmp-updater:kmp-updater-compose:v0.3.0 和传递引入的核心库。仓库解析范围限定为 com.github.zerofancy.kmp-updater。
更新服务https://zp.ntutn.top，公开接口 GET /api/v1/updates。客户端只发送软件内部名、系统、架构和包类型。后台凭据仅用于服务管理。
版本与目标从当前构建的 BuildConfig 读取版本，versionCode 转为 Long 比较，versionName 用于展示。目标由 SDK 检测，支持 Android / ARM64 和 Android / X86_64，包类型固定为 apk。
界面与生命周期主界面的 ViewModel 持有 SDK 的 UpdateController、检查器和下载器，跨旋转保留查询和下载状态。用 AndroidUpdateHost 承载检查、下载和安装界面，传入当前 Activity 和 RESUMED 状态。恢复前台后继续展示原有结果。ViewModel 清理时释放控制器并关闭下载器、检查器，由 SDK 取消任务和清理临时文件。
下载校验服务端声明 SHA-256 或 SHA-512 时，SDK 在写入下载文件的同时计算摘要。摘要一致后发布完成文件。摘要不匹配时显示失败并清理临时文件。未提供摘要的历史发布可继续下载。
安装交接宿主声明 REQUEST_INSTALL_PACKAGES。SDK 合并私有 FileProvider，authority 为 ${applicationId}.kmp-updater.install，映射范围为 files/kmp-updater/。SDK 验证完成文件属于当前应用且版本更高，以临时只读 URI 交接给系统，并保护 APK 供安装器读取。Android 系统负责验证签名和最终安装，应用再次启动时读取实际安装版本。
构建兼容核对合并后的 INTERNET 权限和 Compose 依赖。Release 通过 HTTPS 检查和下载。Debug 默认仅显示版本。用 -PupdateTestServer=true 构建时，默认包名后缀为 .updatetest，可通过 http://127.0.0.1:18763 检查和下载。用 adb reverse tcp:18763 tcp:18763 连接电脑上的测试服务。Debug 的明文网络配置限制在回环地址。

4. 服务登记与发版

  1. 线上软件为 awell（ID 8）。历史版本 1.0.2（3）的分发 ID 为 13，安装包 ID 为 17。1.0.1（2）的分发 ID 为 8，安装包 ID 为 11。Android ARM64 和 X86_64 查询均返回同一份签名 APK。
  2. 正式发版使用 top.ntutn.awell 和与已分发版本兼容的签名证书。核对线上和 APK 的版本号，再为新版分配严格递增的 versionCode。
  3. 在现有服务中发布 apk 分发，按 APK 实际支持的 ABI 配置 Android 目标。若同一 APK 已验证支持 ARM64 和 X86_64，可给同一个包配置两个目标。填写面向用户的纯文本发布说明，供 SDK 弹窗展示。
  4. 逐个查询实际发布的目标，核对版本、下载链接、APK 的包名和签名。首次发版前，可在测试环境用两个同签名版本验证从查询到覆盖安装的路径。

首个含 SDK 的版本仍需通过原分发方式送达。安装该版本后，AWell 才能主动发现后续新版。

5. 验收

2026-11-22：在 Android 15 X86_64 模拟器通过回环更新源验证 1.0.3 (4) 到 1.0.4-test (5) 的应用内覆盖安装。错误的 SHA-256 触发下载失败并清理临时 APK。正确的 SHA-256 下载完成后，验证了首次授权、返回后再次发起安装、取消系统确认后重试。覆盖安装后保留「夜间调暗」设置，再检查时显示「当前已是最新版本」。

2026-11-15：1.0.2（3）正式签名 Release 构建、25 项单元测试及 Release lint 通过，签名与线上 1.0.1 一致。通过发布 API 上传 R2 并创建分发 13（包 17），ARM64 和 X86_64 的公开更新查询均返回新版，线上 APK 的 SHA-256 与本地一致：0e1bf48bb2f3f036d8b189351be198dfed15cf8b8a0e368c48d65cb0009bf3ef。

2026-11-15：安装交接接入后，Debug 与设备测试 APK 构建、25 项单元测试及 lint 通过。NX888J（Android 16）使用独立包名 top.ntutn.awell.installtest 运行 3 项设备测试通过，覆盖只读 content URI、FileProvider 暴露范围及异包 APK 拒绝；未执行真实覆盖安装，首次安装授权往返、拒绝与系统安装器交互仍待人工验收。

2026-11-07 在 NX888J（Android 16，ARM64）验证 1.0 (1) 手动检查、Fennec 下载、Android 安装器覆盖安装及升级后再次检查。下载文件 SHA-256 与签名包一致，首次安装时间与测试设置均保留，1.0.1 (2) 显示「当前已是最新版本」。X86_64 已验证线上查询。

  1. 通过 JitPack 解析固定 SDK 版本后，AWell 能构建 Debug 和正式签名 Release。确认合并权限、最低 API 与包名符合设计。
  2. 在受支持 Android 目标上验证高版本、相同或较低版本、无匹配包、离线或超时。确认不支持的架构不发送查询。
  3. 验证启动和恢复前台时无更新查询，手动检查有结果反馈。旋转、退到后台再恢复和连续点击时，检查触发和弹窗数量符合约定。
  4. 检查应用内下载的进度、取消清理、失败重试、摘要不匹配及旋转和前后台切换。在设备上验证首次授权和拒绝、返回应用再次发起安装、安装器取消后重试及真实覆盖升级。
  5. 在同签名测试包上验证浏览器打开链接、下载及覆盖安装。覆盖安装后核对版本、已选照片目录和壁纸设置。
  6. 服务登记后检查公开 API 返回预期状态。若已有正式分发，核对每个目标返回的 APK 版本和下载链接。
