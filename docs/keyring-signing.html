Gradle 钥匙圈签名

AWell 使用 Gradle Keyring 0.2 读取系统钥匙圈中的 keystore 密码和私钥密码，接法参考 so-novel-reader 的接入。

Release 默认启用签名。仅在 Release 打包任务需要签名信息时读取配置和密码；配置缺失会明确失败，不会自动回退到未签名包。克隆后的 IDE 同步和 Debug 构建不需要 Release 签名配置，Debug 仍使用 Android 默认调试签名。

1. 配置现有 keystore

使用已有 Release keystore，保存在仓库外并备份。不要为已有发布版本随意更换签名身份。本接入不会生成或替换 keystore。

在根目录已被 Git 忽略的 local.properties 中保留 SDK 配置，并加入实际路径和别名：

keyringStoreFile=/absolute/path/to/release.jks
keyringKeyAlias=your-key-alias

路径和别名也支持同名 -P 参数，Gradle 项目属性优先于 local.properties。相对路径从项目根目录解析，~ 不会展开；Windows 路径建议使用正斜杠。

2. 初始化钥匙圈密码

在已登录桌面、钥匙圈已解锁的本机终端执行：

./scripts/init-keyring-signing.sh

脚本隐藏输入，私钥密码留空表示沿用 keystore 密码。密码经短期环境变量传给插件，不写入项目文件或命令行参数。

单独更新密码或在 Windows 上初始化时，可运行插件任务，从标准输入录入密码（Windows 使用 gradlew.bat）：

./gradlew --no-daemon --no-configuration-cache -PkeyringSigning=false :setSecretValue --name=android_store_password
./gradlew --no-daemon --no-configuration-cache -PkeyringSigning=false :setSecretValue --name=android_key_password

macOS 使用登录钥匙串；Linux 需要会话 D-Bus 和 Secret Service 等兼容服务。首次读取可能提示授权或解锁。

当前根项目名是 AWall，对应钥匙圈服务名 Gradle Project AWall，两个密码独立于参考项目保存。更改根项目名后需要重新初始化。

3. 默认构建签名 Release

# 检查 keystore、密码、私钥和证书链
./gradlew :app:verifyReleaseSigning

# 构建签名 APK
./gradlew :app:assembleRelease

# 构建签名 AAB
./gradlew :app:bundleRelease

APK 位于 app/build/outputs/apk/release/app-release.apk，AAB 位于 app/build/outputs/bundle/release/app-release.aab。

Release 签名任务的输入包含密码，因此项目默认关闭 Gradle 配置缓存。显式请求 --configuration-cache 且任务需要 Release 签名时，会在读取密码前失败。用户级或 IDE 配置如果开启了缓存，应关闭或使用 --no-configuration-cache。

IDE 同步、Debug 构建和密码初始化任务无需关闭签名即可运行。只有明确需要生成未签名 Release 包时，才临时关闭签名：

./gradlew :app:assembleDebug
./gradlew -PkeyringSigning=false :app:assembleRelease
./gradlew --no-configuration-cache :listSecretConfigs

keyringSigning 只接受 true 或 false；也可在 local.properties 中设置。显式关闭后构建 Release 会得到未签名包，verifyReleaseSigning 会失败。

CI 与凭据映射

钥匙圈秘密名Gradle 项目属性环境变量
android_store_passwordsignStorePasswordSIGN_STORE_PASSWORD
android_key_passwordsignKeyPasswordSIGN_KEY_PASSWORD

插件读取顺序为项目属性、环境变量、系统钥匙圈。CI 可注入上述环境变量，并通过 -PkeyringStoreFile 和 -PkeyringKeyAlias 提供 keystore 路径和别名，无需桌面钥匙圈。

不要把密码写入受 Git 跟踪的文件或 -P 命令行参数。不要运行会输出密码的 listSecretValues。keystore 与密码均需保留备份。
