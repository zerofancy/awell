AWell · 发布 API 使用说明

协议核对日期 2026-11-15 · 本仓库的发版 agent 接入说明

本地配置请求与响应R2 上传重试与错误分发示例

01 · 本地配置与发布入口

从仓库根目录 local.properties 读取 updaterPublishBaseUrl 和 updaterPublishToken。发布前缀为 https://zp.ntutn.top/api/v1/publish/awell，token 仅绑定软件 awell，具有发布和 R2 上传权限。到期时间记录在配置文件注释中。

向本服务发送单个 Authorization: Bearer <token> 请求头。凭据仅供本地发版客户端使用，保存于被 Git 忽略、权限为 0600 的配置文件中。读取与调用时避免将 token 输出到日志或进程参数，也不得写入 APK、资源或 BuildConfig。

一次分发包含 1–20 个包，各包拥有独立版本号和平台配对。提交分发后立即公开。软件、已有分发和 token 的维护入口为管理后台。构建、包名、签名和 ABI 约定见仓库根目录 AGENTS.md。

公开更新查询为 GET https://zp.ntutn.top/api/v1/updates?software=awell&os=Android&arch=ARM64&packageType=apk。将架构替换为实际目标，发布前后分别核对最高版本和下载信息。

02 · 请求与响应

以下路径相对于 /api/v1/publish/{software}。{software} 是已有软件的精确内部名，鉴权时解析并与 token 所绑 ID 比对。

方法和路径权限成功响应
POST /distributions发布。首次提交中若含 R2 包，另需 R2 权限。201 新建。200 同键同体重放，返回首次提交回执。
POST /uploads发布 + R2201 登记。200 返回同一授权窗口内的原记录。
GET /uploads/{uploadId}发布 + R2200 上传状态。
POST /uploads/{uploadId}/complete发布 + R2200 已校验。202 已有校验在进行，按 Retry-After 查询状态。

路径参数和请求体承载全部业务输入。POST 接受 UTF-8 application/json。拒绝非法 UTF-8、畸形 JSON、重复键、未知字段及类型不匹配。分发请求上限 1 MiB，上传登记和完成请求各 16 KiB，按实际读入字节计量。登记与分发提交需要 Idempotency-Key，值为小写标准 UUID，每个逻辑操作单独生成。

POST /distributions 请求字段

字段规则
title必填。去掉首尾空白后 1–100 个字符，同软件内唯一。
descriptionMarkdown
descriptionPlainText		各自可省略、传 null 或字符串，空白按空内容保存，每项最多 10,000 个 Unicode 码点。沿用现有换行和控制字符校验，服务端按各自原文保存。
packages必填，1–20 项。包的 name 去掉首尾空白后 1–200 个字符，分发内唯一。packageType 为必填小写标识，匹配 [a-z0-9][a-z0-9-]{0,31}。
packages[].versionCode
packages[].versionName		版本号为正的 64 位有符号十进制整数字符串。版本名可省略、传 null 或字符串，上限 100 字符，空值取版本号的十进制表示。
packages[].targets至少一个不重复的 {"os":"Android","arch":"ARM64"} 配对。系统为 Windows、Linux、MacOS、Android，架构为 X86_64、ARM64。仅按明确提交的配对保存。
packages[].source 为 external必填 downloadUrl，为最多 2048 字符且含主机、不含用户信息的 HTTP(S) 地址，服务端只校验格式。packageSize 为非负的 64 位有符号十进制整数字符串、null 或省略。允许可选的 checksumAlgorithm / checksumValue，规则见下文；不接受 uploadId。
packages[].source 为 r2必填 uploadId。仅接收当前 token 持有的、尚未关联且在关联期限内的 READY 上传。下载地址、大小和 checksum 均取自上传记录的不可变快照。来源信息仅接收 uploadId；客户端出现 downloadUrl、packageSize、checksumAlgorithm 或 checksumValue 任一字段即返回 400 INVALID_REQUEST，即使值为 null 也不接受。

文本沿用现有单行和描述校验。64 位整数输入只接收 ASCII 十进制数字，防止 JSON 数值精度丢失。同软件、系统、架构、包类型、版本号的组合须唯一。API 允许一次请求混用外链与 R2 包。

Checksum 输入合同（2026-11-15 扩展）

每包最多一组可选 checksum，代表最终下载文件完整原始字节的发布者声明摘要。仅支持 sha512（SHA-512，128 位十六进制，默认）和 sha256（SHA-256，64 位十六进制）；不是内容实测结果，不支持 MD5、SHA-1 或算法别名。

  • 两字段均省略，或两字符串移除首尾 ASCII 空格、TAB、CR、LF 后均为空，表示不配置。非空值配省略或空算法时默认 sha512，不按摘要长度猜算法；仅算法非空而值为空则拒绝。
  • 字段出现时必须是字符串；显式 JSON null、数字、数组、对象、重复键均返回 400 INVALID_REQUEST。规范化前算法最多 32 字符、值最多 256 字符；去掉上述 ASCII 首尾空白后转小写，值严格为对应长度的 [0-9a-f]。不接受内部空白、Unicode 相似字符、SHA-256、0x、前缀、Base64 或带文件名的 shasum 输出。
  • external 包在发布 JSON 的包对象内提交这两项；r2 包在上传登记时提交，发布时只能用 uploadId 引用，不允许覆盖。JSON API 不接收网页用的 checksum_form / checksum_enabled 开关。
  • 格式错误按既有错误协议返回，发布字段路径如 packages[0].checksumValue。任一包非法，整次发布失败。服务端不下载外链、不计算 R2 全文件摘要，不新增 CHECKSUM_MISMATCH 或 verified 语义。

示例：external 包可附加 "checksumAlgorithm":"sha256","checksumValue":"ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"。该值仅演示合法格式，不声称匹配本文示例安装包。客户端应对真实下载文件自行验证。

成功回执

{
  "software": "awell",
  "distributionId": "42",
  "publishedAt": "2026-11-11T06:00:00Z",
  "packages": [
    {
      "packageId": "105",
      "name": "Android ARM64",
      "downloadUrl": "https://files.example.org/awell-arm64.apk",
      "packageSize": "1849020",
      "checksumAlgorithm": null,
      "checksumValue": null
    }

ID、已知包大小用字符串，未知大小用 null，时间戳用 UTC ISO 8601。包按提交顺序返回。新建回执的每个包始终含 checksumAlgorithm / checksumValue，来自事务实际保存的包；未提供时均为 null。历史回执不重写：旧幂等键逐字返回首次保存的旧 JSON，允许缺少新字段，客户端须兼容。响应 null 不代表请求可提交 null。回执表示分发已经提交，后续网页编辑或删除后的状态以公开下载页和更新检测结果为准。

03 · R2 上传

  1. 登记。 POST /uploads 提交 {"filename":"awell-arm64.apk","size":"1849020"}。成功给出 uploadId、filename、status、expiresAt、completionDeadline、attachBefore，登记响应另外给出 uploadUrl、method、headers 和 maxFileSize。登记可附加可选字符串 checksumAlgorithm / checksumValue，遵守上述统一格式合同；未配置的旧请求仍有效。创建成功、查询及 complete 的 200/201 响应均包含这两字段，未提供时均为 null；202 等待响应维持精简格式。checksum 与上传记录首次签发时一同持久化，之后不可修改，补充或更改需新上传。授权窗口内，以同一键、同一文件名、字节数及规范化后的 checksum 重试返回原记录，不延长授权；省略算法与显式 sha512 配同一摘要等价，改变算法、摘要或有无配置产生既有幂等冲突。过期后查询已知上传 ID，确认需要重新上传时使用新登记键。
  2. 直传。 按响应返回的 PUT、URL 和 Content-Type: application/octet-stream 将文件发送给 R2。发布 token 只发送到 updater-server，安装包文件体只发送到 R2。 R2 预签名上传文档
  3. 完成校验。 POST /uploads/{uploadId}/complete 提交 {}。complete 不接受补交或修改 checksum。服务端复用 HEAD 校验、源 ETag 条件复制及正式对象校验；READY 不表示 checksum 与内容相符，服务端不读取全文件、不用 ETag 代替摘要、不增加 S3 checksum 请求头或修改 PUT 的 Content-Type/CORS 约定。202 时按 Retry-After 查询状态，继续 VERIFYING 则退避轮询。持续等待达到校验租约上限（120 秒）或收到可重试的校验错误时，可再次提交完成请求。PUT 响应丢失时先尝试完成校验，OBJECT_NOT_FOUND 后可在签名有效期内补传。GET 与完成响应在 READY 或 ATTACHED 状态给出 downloadUrl 与实测 size，不返回预签名 URL。
  4. 关联。 以 {"source":"r2","uploadId":"…"} 指定包来源，分发提交后状态成为 ATTACHED。每个上传最多关联一个包。分发提交失败时，已校验上传可在期限内用于修正后的提交。

上传记录按 token ID 隔离。登记幂等键在各 token 内独立，查询、完成校验领取租约、分发关联均核对归属。未知或其他主体的上传在查询、校验和关联时一律返回 404 UPLOAD_NOT_FOUND。迁移前的上传归网页管理员。网页可编辑 API 发布的分发并保留原包的既有 R2 关联，新增关联仅取网页上传。

期限与撤销。 沿用现有 R2 大小配置、默认 15 分钟 PUT 授权、24 小时校验截止及 7 天首次关联期限。撤销后服务端拒绝该 token 的后续请求。已经签发的 PUT URL 到期前仍可写入临时对象，已获准的校验可结束，发布仍须在提交事务中通过授权。公开桶中的正式对象可能在分发提交前即可下载。现有清理只处理临时对象，未关联的正式对象也会保留。

04 · 重试与错误

一次逻辑发布对应一个键和一份请求文件

  1. 调用方在首次发送前持久保存 UUID 和完整 JSON 文件。分发幂等域为软件 ID 和该 UUID，指纹为 UTF-8 请求体原始字节的 SHA-256。字段重排、空格或换行变化也会改变指纹。发布 checksum 的大小写、空白、算法省略等即使解析后等价，也不改变这里的原始字节幂等比较规则；与上传登记的规范化比较不同。
  2. 服务端在同一 SQLite 写事务中复核 token 与软件权限，先查已成功回执，再做新发布需要的上传就绪和业务校验。回执相同则返回 200，可在同软件 token 轮换后确认。回执同键异体则返回 409 IDEMPOTENCY_CONFLICT。
  3. 首次发布写入分发、全部包与平台配对、R2 关联及幂等回执，一次提交。任何写入失败整体回滚。已成功回执持久保留，分发日后被编辑或删除时，旧请求仍返回原回执，不会重建分发。回执与新建分发的发布者 token ID 一起记录。
  4. 遇到断线、超时或可重试的服务端错误，以原键、原文件重试，并遵守 Retry-After。明确校验失败后可修正输入，内容改变时生成新键。提交结果未知时先用原请求确认，避免通过改标题或换键绕过冲突。

错误结构

{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "该更新序列已存在相同版本号",
    "retryable": false,
    "fields": {"packages[0].versionCode": "与现有软件包重复"}
  }
}

fields 为 JSON 字段路径到提示的映射，无字段错误时省略。调用方按状态码、code 和 retryable 处理。下表为应用生成的响应，代理网络故障按结果未知处理。

HTTP机器码或场景调用方处理
400 / 413 / 415INVALID_REQUEST / PAYLOAD_TOO_LARGE（请求体）或 FILE_TOO_LARGE（R2 文件）/ UNSUPPORTED_MEDIA_TYPE修正输入。
401UNAUTHORIZED。缺失、无效、过期或已撤销的凭据，统一返回 WWW-Authenticate: Bearer realm="updater-publish"。检查凭据。换 token 后仍可用原请求确认发布结果。
403 / 404FORBIDDEN（软件或权限不符）/ UPLOAD_NOT_FOUND检查目标与授权。软件越界与不存在统一返回 403。
409IDEMPOTENCY_CONFLICT、DISTRIBUTION_TITLE_CONFLICT、VERSION_CONFLICT，或上传的 STATE_CONFLICT、OBJECT_NOT_FOUND、SIZE_MISMATCH、TYPE_MISMATCH、OBJECT_CHANGED。分发冲突需查明原因。R2 的 OBJECT_NOT_FOUND 可在文件送达后重试完成校验。
410UPLOAD_EXPIRED如仍需上传，使用新登记键，更新待提交的包来源。
429RATE_LIMITED等待 Retry-After，再重试原操作。
500 / 502 / 503INTERNAL_ERROR / STORAGE_ERROR / DATABASE_BUSY、STORAGE_UNAVAILABLE 或 UPLOAD_DISABLED。临时错误可用原键重试。UPLOAD_DISABLED 需处理实例配置，或在确认未提交后改用外链包。

05 · 外链分发请求示例

将以下内容保存为 JSON 文件，提交到 updaterPublishBaseUrl 下的 POST /distributions。版本号、标题、大小和地址均为占位示例，发版时读取实际 APK 信息。多个 APK 各占一个包，按实际支持的架构填写 targets。

{
  "title": "示例发布",
  "descriptionMarkdown": "## 本次更新\n- 更新说明",
  "descriptionPlainText": "本次更新\n- 更新说明",
  "packages": [
    {
      "name": "Android ARM64",
      "packageType": "apk",
      "versionCode": "1",
      "versionName": "示例版本",
      "targets": [
        {
          "os": "Android",
          "arch": "ARM64"
        }
      ],
      "source": "external",
      "downloadUrl": "https://downloads.example.org/awell-arm64.apk",
      "packageSize": "123456"
    }
  ]
}

使用 R2 时先完成上传登记与校验，再把对应包的来源改为 "source":"r2"，填写返回的 uploadId 并移除外链字段及 checksum 字段。checksum 如需提供，应在上传登记时提交。向发布接口发送保存好的 UTF-8 JSON 文件，配合持久保存的 Idempotency-Key，以便结果未知时原样重试。
